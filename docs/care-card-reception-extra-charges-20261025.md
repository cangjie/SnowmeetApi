# 养护开单购卡与卡外补费（2026-10-25）

本次用户明确修正：选购卡后，服务项目不因卡种互斥；卡覆盖的部分抵扣，其他项目和维修附加费累加。单项卡同时选修刃、热蜡时，按现有门店「双项价－单项价」补差价，用户已确认。

## 计费与持久化

- 次卡按每件装备核销一次。双项卡抵扣已选修刃、热蜡；单项卡抵扣其中一项，同时选两项时优先在预览中列明修刃为卡内项目。套餐补差和加急差额读取现有门店商品价格，缺配置报错，不按零元放行。
- 机打蜡季卡仍限一套装备，默认机打蜡，允许增加项目；加价沿用现有机打蜡季卡/券12商品优惠规则。只有打蜡季卡绑定装备。
- 维修附加费另计，保留店员手工减免；金额按分取整，补费不为负数。仅做维修等未使用卡权益的装备不扣次数。
- `CareCardSale/Preview` 返回 `cardAmount`、`careAmount`、`amount`（二者合计），及每件装备的卡外服务费、维修附加费、减免和净额。
- 仍由关联零售订单一次收取合计金额：卡销售明细保留原价，卡外费用另存原 `retail` 表的一条 `retail_type=养护附加费用`、`product_id=NULL` 的明细。`care` 保留实际选择和费用字段；关联养护单的订单金额仍为零，防止再次收款或重复统计同一笔合并收入。
- 没有新增表或列，不需要 SQL。没有伪造第二笔第三方支付或拆写支付流水。
- 付款前的项目及费用快照仍放在卡销售行的 `retail.memo`。提交前重新计算并核对金额、项目及明细；发生变化必须重新试算。支付成功后校验实收已足额，再原子发卡、扣次、建任务并清理卡行的临时快照。
- 发卡只处理卡销售行，补费行不会生成卡，也不会计入购卡张数。含卡订单不退款；取消养护只返还该装备实际核销的次数，补费明细保留。

## 兼容与客户端

普通养护、自助购卡接口和旧请求参数不变。订单响应的 `careCardSale` 只增加可选展示字段 `cardAmount/careAmount`；旧客户端普通流程不使用本次补费逻辑。已提交的旧购卡单保留原快照结算，不按新项目规则重新试算。

开单、选卡试算、结算和零售详情分别显示卡款、养护费用及合计。项目按钮不再按单项卡强制互斥，附加费和减免不会被试算回填清零。前一轮结算跳转失败时保留原订单、重试不重建订单的修复保留。
