# 手机号授权接待后自动验证订单身份（2026-10-25）

接待页输入会员手机号、经过店长授权后进入接待，后续订单应自动标记为身份已验证；使用原顾客的券、次卡、季卡或储值时，沿用已验证身份，不再强制原顾客本人微信付款。

## 实现

- 扩展服务端 `OrderVerifiedRules.CheckinVouches` 和 `QrCodeController.ResolveReceptOrderVerified`：当前开单店员、订单会员匹配的当天手机号接待记录，在 `authed=1`、`stoped=0` 且为有效接待码时，可以担保订单身份。原本人扫码的 60 分钟规则保持原样。
- 接待页已支持店长直接进入、普通店员等待批准及当天授权复用，本次不改变这些授权入口和有效期。
- 订单保存采用服务端接待记录判定，不采信客户端传来的身份验证布尔值。已有验证状态在会员不变时保留；更换会员且没有新会员的有效接待凭据时清除。
- 历史字段 `order.wechat_unverified=1` 实际表示“身份已验证”。状态变化继续写入现有修改日志，并记录接待记录 ID。
- 使用现有支付身份逻辑：已验证的养护订单允许他人代付，即使代付人点选“本人”，也不改变原顾客归属。付款人记录在支付单，券、卡次数和养护记录仍属于原顾客；储值按现有储值核销流程扣原顾客账户。

不新增表列、不新增接口参数、不要求更新小程序，不批量修改历史订单。储值仍按既有规则核销，本次不新增储值与外部支付的拆分付款能力。
