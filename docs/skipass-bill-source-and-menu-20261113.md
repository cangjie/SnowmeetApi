# 雪票 H5 对账来源与顶部菜单（2026-11-13）

用户说明：去年使用万龙自我游账号，今年改回大好河山；要求把雪票对账入口放进报表顶部菜单。页面地址保持 `/background/skipass/dhhs_list.html`。

## 修改

- 共享 `background/js/menu.js` 增加“雪票对账单”，销售、养护、租赁及雪票等使用该菜单的页面均能直接进入。
- 雪票页默认大好河山，另可选择万龙自我游历史账号；标题和下载文件名随账号变化，表头使用“供应商单号”。
- 旧页面实际从 `ziwoyou_order` 读取缓存；原同步入口默认万龙账号，改页面标题不能切换账号。本次新增 `core/WanlongZiwoyouHelper/GetSupplierOrderBills`，通过所选账号逐页实时查询供应商订单，再按供应商单号关联本地票、订单、收退款和分账。
- 新接口只允许在职店员查询，与现有供应商成本可见性规则相同。供应商失败或分页不完整返回错误，不把失败或部分账单显示为完整的零元结果。
- 一张本地订单可能有多张票：收款按票成交价分配到分，累计取整保持总额不变；已标注 `payment_refund.skipass_id` 的退款直接归对应票，历史未标注退款按票价分配。分账使用现有有效且成功的记录；不再读取已废弃的付款 `shares` 字段。
- 供应商后台直订仍展示，按原口径不加入本系统合计。取消票的供应商成本为零，收款与退款保留实际发生额。
- 切换账号取消旧请求，旧响应不能回填；每次查询清空原导出内容，防止重复导出旧行。查询失败和登录失效有明确提示，CSV正确处理逗号、引号与换行。

## 兼容与范围

原 `GetOrderBills`、历史缓存和同步接口保留，不更改其请求或返回；新增接口不影响普通小程序订票、付款、核销、退款流程。无数据库结构或业务数据修改，不替换供应商凭据，不写入对账缓存。供应商正常接口访问仍沿用既有 `web_api_log` 日志机制。

## 首次上线验收发现的旧接口故障

用户批准部署后，`b02b258e` 于16:55:00发布，服务和新页面正常，但仍打开旧页面的请求触发 `GetOrderBills` 500。日志明确为 `Include(o.availablePayments)`：该属性是 `[NotMapped]` 计算属性，EF不能Include它。已用本地SQLite用例复现相同异常。

修复改为加载实际的 `payments` 导航，继续由原 `availablePayments` getter维持旧响应；退款加载条件修正为已成功或具有退款单号，避免漏掉已受理退款、载入未发起记录。新增回归同时检查原列表结构、100元收款和60元退款。没有改旧接口路由、参数或响应结构。
